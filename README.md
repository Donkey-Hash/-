## 3. 复位问题摘要（面向现场定位）

现象：多总线 Modbus 通信运行一段时间后卡死，最终喂狗失败触发 IWDG 复位。

最典型、最致命的一类根因举例：

- **寄存器缓冲区长度不足导致越界写**  
  示例：协议栈宏定义为 `REG_HOLDING_NREGS=512`，但某条总线独立映射只分配 `usRegHoldingBufX[110]`。当主站访问更大地址范围时发生越界写，破坏 RAM（任务控制块/队列/互斥量等），表现为“运行一段时间后随机卡死/复位”。

详细过程与修复点见：

- `Modbus_MB3_卡死复位_越界排查记录.md`

## 4. DMA + 串口空闲中断（IDLE）结论（摘要）

- 建议评估并分阶段落地：先做可观测性（统计计数）→ 再在单路（推荐 MB3/USART3）试点 RX DMA+IDLE → 最后推广到三路
- 注意：UART 的 **IDLE 不等价于 Modbus-RTU 的 t3.5**，建议把 IDLE 当作“收包暂停提示”，帧边界最终仍由 t3.5 判定/确认

完整评估与落地步骤见：

- `DMA_UART_IDLE_多总线Modbus_评估方案.md`
